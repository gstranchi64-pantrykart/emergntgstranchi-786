# RCA — Deploy failed at `pull_source` (missing `backend/.env`)

**Deployment:** github-integration-27 (`c2fb56c0-d8ab-4797-b543-0a90bb6e2ef2`)
**Template:** fastapi_react_mongo_shadcn_base_image (farm) · arm64 · tier_0 · frontend_type=cloudflare
**Failed runs:** `8af0dfdb-5206-4b53-9b36-6be7ac714ee3` (initial), `87013b9a-ce60-4090-bb4a-56f7518abd1b` (retry)
**Failed step:** `pull_source` (before build — no Cloud Build ever started)

## What happened
Both runs failed in `pull_source` → "prepare build context: read envs" with:

```
read env file backend/.env: open /tmp/agent-env-.../app/backend/.env: no such file or directory (PathError)
```

The farm template's `config.yaml` declares:
```yaml
env_paths:
  - "backend/.env"
  - "frontend/.env"
```
`pull_source` must read every file in `env_paths` to capture the backend's environment variables (e.g. MONGO_URL, DB_NAME, and any app keys) and fold them into the deployment secret store. `backend/.env` does not exist in the pulled source, so the step aborts before the Docker build.

## Why it is not transient
I retried `resume_pipeline` once. The retry produced a brand-new run with a different agent-env mount path (`...-1790962049073296243`) and failed at the identical point. A mid-sync/partial dump would not reproduce byte-for-byte on a fresh pull — so the file is genuinely absent from the source, not momentarily missing.

## Root cause
The backend has no `.env` file in the preview/agent-env source. A FARM backend requires one (at minimum `DB_NAME`, and typically `MONGO_URL` and any app-specific keys); the deployer treats it as a required input via `env_paths`.

## Fix (owner: E1 / source)
Create `backend/.env` in the preview environment with the backend's expected variables, e.g.:
```
MONGO_URL=mongodb://localhost:27017
DB_NAME=github_integration_27
# + any app-specific keys the backend reads
```
Then redeploy. On the next deploy `pull_source` will find the file, capture the vars, and proceed.

## Not done / rejected alternative
I did NOT remove `backend/.env` from `config.yaml` `env_paths`. That would let `pull_source` pass but ship a backend with no environment configuration, which would crash at runtime (missing DB_NAME/MONGO_URL) — it masks the problem rather than fixing it.
